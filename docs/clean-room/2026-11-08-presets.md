# Gimbal presets

## Source and method

2026-11-08, USBPcap on `\\.\USBPcap3` while using the preset controls
in OBSBOT Center, and a black-box test with a temporary preset in
Gimbly. OBSBOT Tiny 3 Lite (`3564:ff04`, USB descriptor revision
`0x0510`), Windows 10 Pro 19045. The firmware release and OBSBOT
Center version were not recorded.

## Observed in the USB capture

Commands use extension unit 2, selector 2, interface 0 and gimbal address
`04`. Multi-byte values are little-endian.

| Operation | Command | Request data | Reply data |
| --- | --- | --- | --- |
| List | `04 3d` | None | One byte per ID, e.g. `00 01 02` |
| Name | `c4 3c` | u32 ID | Name bytes, ASCII in the capture, no terminator |
| Stored position | `44 3a` | u32 ID and a zero byte | 24 bytes, beginning with u32 ID and four i16 values for yaw, pitch, roll and zoom |
| Go to | `c4 39` | u32 ID and four f32 values of 1.0 | None requested |
| Current position | `04 66` | None | 24 bytes, including i16 pitch and yaw at offsets 8 and 10 |
| Store | `44 39` | u32 ID, then i16 yaw, pitch, roll, zoom, and `-200, -200, 300, 300, 0, 0` | None requested |
| Name write | `84 3a` | u32 ID followed by name bytes | None requested |
| Delete | `84 39` | u32 ID | None requested |

Center reads the current position and zoom before saving the first free
slot, then writes the default name. Current angles use tenths of a
degree. Stored angles and zoom use hundredths. For example, the current
reply had pitch 332 and yaw −142, which were written as −1420 and 3320
in the new preset. The idle `04 01` reply ended in a u16 count that
agreed with the length of the list from `04 3d`.

## Observed in Gimbly

- A yaw-only move changed the first angle in the stored position.
  A subsequent pitch-only move changed the second. Zoom set with
  `42 19` was read with `04 68` and stored with the position.
- A position write to an existing ID replaced the position and cleared
  the custom name. Gimbly reads the name before writing the new position
  and writes it back afterward. The final readback kept the test name
  while pitch changed from 3.2° to 16.2° and zoom from 2.5× to 1.5×.
- Recall moved the camera and restored the stored zoom using only
  `c4 39`. Delete removed the temporary ID from the list using only
  `84 39`.
- Back-to-back writes produced intermittent readback failures. With at
  least 20 ms between writes, as in the Center capture, the name and
  position were readable after changes.

## Unknown

The purpose of the trailing fields in stored positions and the extra
`c4 3d` and `84 3d` messages around recall and delete is unknown.
Gimbly uses the captured store fields and supports printable ASCII
names. Other encodings and the official app's own Update PTZ traffic
were not established.

## Test

`camera::vendor::tests::preset_commands_match_capture` and
`camera::vendor::tests::decodes_preset_replies` compare the captured
payloads and reject invalid lengths and IDs. The hardware probe
(`gimbly --probe --gimbal DIR`) exercised add, rename, update, recall and
delete in slot 2 and compared saved frames and preset readback.
